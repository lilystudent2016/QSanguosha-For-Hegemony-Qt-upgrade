# 国战专属规格（写国战代码必读）

> **定位**：本文件是国战方向的**操作手册**。
> 「**过程**」（结算流程 / 时机 / 用语）以**官方规则集**为准；
> 「**内容**」（某个技能当前长什么样）以**目标项目现役代码**为准。
> 完整规格（含逐人数展开表 + 5 项**裁定结论**）在 **`code_sgs/data/国战模式规格.md`**，本文件是其提炼版。

## 0. ★★ 第一原则：bot 落地与训练**一律以项目实现为准**

用户裁定（2026-09-18）：**项目按线下人数设计，支持 2–12 人**，不受官方线上 4~8 人限制。
**落到项目处做 bot 训练/数据标定时，一律取「项目实现口径」**；
规范值、说明页值只作**对照与报备**，**不作为训练标签的生成依据**。

理由：训练集若用规范口径打标、宿主却按实现口径运行，**标签与宿主会系统性错位**。

推理链（**不要凭感觉改**）：改宿主 → 必须走 `freekill-core` + `deploycore.sh`（D6），
且规则改动**先报用户裁定**（D7）。→ 所以默认动作是「**跟着实现走 + 把差异报备**」，不是「改了它」。

## 1. 五参数：项目实现口径（★ 训练基线）

X = 玩家数 = 游戏总角色数。**写国战代码时这 5 个参数必须集中成「以 X 为输入的函数」**，
不要散落成 if —— 否则 2~3 人与 9~12 人局必然错。

### 1.0 ★★ 已裁定训练取值（用户裁定 2026-09-18 结案）—— **打标直接用这张**

| 代号 | **★ 训练取值** | 与【实现】 |
|---|---|---|
| **A** 鏖战阈值 `T` | **三方取最大**（「取人数多的」，加速进程）：X≤6 → **3**｜X=7~9 → **4**｜X=10,11 → **5**｜X=12 → **6** | ❌ X=10~12 大 1<br>（**8~9 人主样本无差异**） |
| **B** 野心家门槛 | `N_min = ⌊X/2⌋ + 1`（奇数 X 即 `(X+1)/2`）<br>X=2→2｜3→2｜4→3｜5→3｜**6→4**｜**7→4**｜8→5｜**9→5**｜10→6｜11→6｜12→7<br>⇒ **同势力最多 `⌊X/2⌋` 人**保持非野心家；**君主存活则豁免** | ✔ 一致 |
| **C** 阵法技门控 | **不补门控 → 4 人以下保留阵法技**（也不过滤阵法技武将） | ✔ 一致 |
| **D** 阵法召唤④ | **含已死亡**（`include_dead = true`） | ✔ 一致 |
| **E** 鏖战效果 | **2019 版**（【桃】当【杀】【闪】）→ `old_battle_royal = true` | ✔ 只定默认值 |

> **A**：线上项目有意**加速进程不拖时间**；训练录像取 8~10 人，该差异基本不影响判断。
> **B**：★权威实现 = **`freekill-core/ltk/server/serverplayer.lua:573-585`**（首次明置确定势力时）：
> `其他同势力角色数(已明置·含已死亡) >= X//2` → 变 `wild`；`table.every(room.alive_players, ... not lord)`
> ⇒ **该势力君主存活则豁免**。用户描述已逐条核对 ✔（**7 人第 4 个、9 人第 5 个**）。
> ⚠️ 只数**已明置**的同势力（暗置者 `kingdom == "unknown"` 不计）；配额满了之后**继续明置的也都变野心家**。
> 配套：**君主死亡 → 同势力已明置角色均变野心家**（`new_hegemony_mode.lua:583-596`；
> 旧项目 `gamerule.cpp:898-909`）；君主明置 → 拉回（`hegemony_rule.lua:206-216`）。
> **C**：FreeKill 现状本就无门控，且其**现行说明页**（`new_hegemony_mode.lua:104`）
> 已把口径改成「**处于阵法关系时**锁定生效」、删掉了「存活≥4」→ 与裁定同向。
> ⚠️ 但【规范】`:1055`、【旧项目】`formation.cpp:569`、**【resgs_v1】`core/skill/effect.ts:155`（`aliveCount < 4` 则不生效）**
> 都是「**有门控**」→ 属用户主动选择，已报备。
> **D**：源码注释 `util.lua:84` `@param include_dead? boolean @ 包括死人` 即证据。
> ⚠️ 【resgs_v1】的阵法召唤**完全没有人数条件④**（`extensions/wars/rules.ts:141-200`），仅作参照。
> **E**：录像全部是 2019 规则；2026 版（【桃】当【酒】）**2026-08 才上线、暂无录像可训** → 保留开关以后再议。

**五参数原表（【实现】×【规范】对照，供追溯；★训练取值以上表 1.0 为准）**：

| 代号 | 参数 | 【实现】（宿主实际行为） | 出处（实现） | 【规范】 |
|---|---|---|---|---|
| **A** | 鏖战触发阈值（存活 **≤ T**） | `T = (X > 6) ? 4 : 3` | `hegemony_rule.lua:45` | `3+sgn(X−7)`（`主规则集.md:1909`） |
| **B** | 野心家阈值 | `其他同势力(已明置·含已死亡) >= X//2`（⟺ `N > X//2`；**君主存活豁免**） | **`freekill-core/ltk/server/serverplayer.lua:576`** | `其他角色数 + 已死亡该势力数 ≥ X/2`（`:2545`，**不取整**） |
| **C** | 阵法技有效门控 | **未实现**（真缺口） | — | `角色数 ≥ 4`（`:1055`） |
| **D** | 阵法召唤条件④ | `getKingdomPlayersNum(room,true)[kg] < X // 2` | `util.lua:352` | `与A同势力角色数 < X/2`（`:1067`） |
| **E** | 游戏结束／胜利 | `i > X // 2 且无君主 → 不判胜`；**有君主允许判胜** | `new_hegemony_mode.lua:496-505` | `(存活+该势力已死亡) ≤ X/2` **且无君主**（`:2916`） |

> ⚠️ B 的 `util.lua:75`（`i > X//2 and not lord`）**不是赋值处**，只是 `compareExpectedKingdomWith`
> 里对同一规则的**近似引用**（用于判断暗置者该不该当敌人）；真正把 `kingdom` 改成 `wild` 的是上面那行。

**A 的附加条件**（别漏）：`#room.alive_players < T` **且** 没有任何势力**存活数 > 1**
（`hegemony_rule.lua:45-52`）→ 即规范说的「没有势力相同的两名角色」。

### 1.1 ★ 取整差异的正确判读（**只看比较符**，别一律怪 `//2`）

| 形式 | 取整有影响吗 | 谁 |
|---|---|---|
| `i > X // 2` | **无影响**（整数 i 下 ⟺ `i > X/2`） | **E** |
| `k >= X // 2` | **有影响**：奇数 X **宽 1** | **B** |
| `k < X // 2` | **有影响**：奇数 X **严 1** | **D** |
| `alive < 常量` | 不适用 | **A**（实现根本不是 /2 形式） |

> 规律：`>` 对向下取整**免疫**；`>=` 与 `<` 都会差 1（奇数 X）。

### 1.2 差异速查（实现 × 规范）

| 参数 | 差异 |
|---|---|
| **A** | X≥8 实现与规范**完全一致**；X≤7 实现晚 1。三套（规范/说明页/实现）**只有 X=8、9 一致**。★裁定=取最大（见 1.0） |
| **B** | **三项目实现彼此一致**（FreeKill `serverplayer.lua:576`＝老项目 `serverplayer.cpp:1826`＝印刷本 `new_heg/…/hegemony.lua:117`）；**只有【规范】`:2545` 奇数 X 晚 1 位**（要求 `≥⌈X/2⌉`）。★裁定=取实现 |
| **C** | 实现**无门控**；旧项目**有**（`formation.cpp:569`）；**resgs_v1 也有**（`core/skill/effect.ts:155`）。★裁定=**保持无门控** |
| **D** | 奇数 X 实现**严格 1**（更难召唤）；实现**含已死亡**；旧项目该条**被注释停用**；resgs_v1 **无此条件**。★裁定=含已死亡 |
| **E** | 阈值侧一致；**君主分支不等价**（规范要求「无君主」，实现是「有君主就放行」）→ 报备。★裁定=2019 版效果 |

⚠️ **2 人局**：A 的裁定阈值 = **3**，而开局存活 = 2 → 只要双方**势力不同**，
**第一个回合开始即进入鏖战**。

### 1.3 5 项裁定结论（2026-09-18 结案）

见 **1.0**。三句话记住：**A 取大、B/D 照实现、C 不补门控、E 用 2019**。

> E 的开关：`room:getSettings("old_battle_royal")` / `HegUtil.enterBattleRoyalMode`（`util.lua:900-921`）；
> 两套技能都在 —— `skills/battle_royal.lua`（2019）、`skills/new_battle_royal.lua`（2026）。
> 规范（`:2049`/`:2273`）与印刷本**都是 2019 版** → 默认 2019。已结案，**不要再当开放问题问用户**。

## 2. 结构级差异（不是措辞问题，直接影响代码结构）

1. **多目标牌要选结算方向**。【桃园结义】【五谷丰登】【南蛮入侵】【万箭齐发】国战版比身份版多一条
   执行动作：「你在选择目标的同时**选择结算的方向**（从当前回合角色开始按顺时针或逆时针）」。
   → 结算顺序**使用者可选，不能写死**。
   （印刷本页码：桃园 p163、五谷 p172、南蛮 p157、万箭 p167；复核 `--grep-print 结算的方向`）
   ⚠️ **两侧项目（FreeKill / 旧项目）都没有实现** → **真缺口**；
   bot 若按身份版顺序写死，方向选择类决策点会系统性偏离。
2. **国战【连弩】≠ 身份版【诸葛连弩】**。印刷本国战【连弩】（♣A/♦A）＝「使用【杀】**次数上限 +3**」；
   身份版【诸葛连弩】＝「**无次数限制**」。
   ⚠️ **两侧项目的实际实现都是「无次数限制」**（FreeKill 直接复用 `crossbow`，
   `standard_cards/init.lua:142`；旧项目 lang 也只有 `["Crossbow"]="诸葛连弩"`）。
   → 按「内容以项目为准」= **保持现状**，但**必须报备**（印刷本 × 项目的冲突，不擅自改）。
3. **国战改词与结构变化**：
   - 词：「其他角色」→「**对手／队友**」；「一名其他角色」→「有牌的对手」；「你的下家」→「与你同一队列」。
   - 结构：常从**单效果变双选项**。例【过河拆桥】身份＝弃一张；国战＝选择 1.弃其装备区一张 2.看其手牌弃一张（印刷本 p146）。
   - 变体：【铁索连环】【金蝉脱壳】【勠力同心】等在国战版是「使用方法①②」并列，对应不同使用时机/目标。
4. **暗置武将牌没有技能、性别、势力** → **势力推断必须自己算**。
5. **阵法关系（围攻／队列／对垒）全部座次敏感**；**不计入座次**的角色使相邻关系**顺延**（`主规则集.md:1051`）。
   不计入座次的角色：与所有其他角色均不相邻、不处于任何围攻/队列；判断时**视为已离场**。
   三种关系：**围攻**＝上家和下家势力相同且与该角色不同；**队列**＝至少两名势力相同的角色连续相邻；
   **对垒**＝对家已明确势力且与其不同。（实现基类 `HegUtil.ArraySummonSkill`，`util.lua:341-378`）
6. **明置的三条途径**：①发动技能（被动）②有锁定技的武将于**出牌阶段**可主动明置
   ③每名玩家于**自己回合开始时**可明置 1~2 张。**均明置后性别以主将为准**。
7. **预亮**：部分**触发技**需先「预亮」，系统才会在相应时机询问 → **不预亮 = 放弃该技能**（bot 同此）。

**国战牌堆实测（`hegemony/pkg/standard_cards/init.lua`）：共 108 张**

| 类别 | 张数 | 备注 |
|---|---|---|
| 【杀】 | 29 | 普杀 21 / 雷杀 5 / 火杀 3 |
| 【闪】 | 14 | |
| 【桃】 | 8 | |
| 【酒】 | 3 | |
| 锦囊 | 27 | 顺3 拆3 铁索3 南蛮2 五谷1 万箭1 桃源1 决斗2 借刀1 无中2 无懈1 乐2 火攻2 兵粮2 |
| **国战专属锦囊 9 张** | 9 | **远交近攻** 1、**知己知彼** 2、**以逸待劳** 2、**无懈可击·国** 2 |
| 装备 | 17 | 含 **吴六剑** 1（同势力其他角色攻击范围+1）、**三尖两刃刀** 1；【连弩】= `crossbow` × 1 |

**专属牌技能文案**（`standard_cards/skills/*.lua`）：
- **远交近攻**：选择势力与你不同的一名角色，其摸一张，你摸三张。
- **知己知彼**：观看目标一张暗置武将牌**或**其手牌（二选一）。
- **以逸待劳**：`multiple_targets`；你和与你势力相同的角色各摸两张，然后各弃两张。
- **无懈可击·国**：除常规抵消外，可令「与其势力相同的角色为目标结算的此牌」不是【无懈可击】的合法目标。

**其他卡牌层机制**：
- **势力锦囊**（不臣篇）：使用者已明确势力且与锦囊相同 → 得额外效果，否则仅基础效果；
  置入弃牌堆后**移出游戏**；**不能转化**。
- **奇珍牌**（九变篇）：九变篇装备牌均为奇珍牌；拥有者受到【杀】伤害后，伤害来源可获其一张奇珍牌
  （`hegemony_rule.lua:289-319`，`rare_treasure`）。
- **合纵**（势备篇）：牌上标「合」。出牌阶段限一次，二选一：①已确定势力 → 至多三张「合」牌交给**不同势力**角色，
  摸等量；②交给**未确定势力**角色。口诀：**出限一、限三张、摸等量；给明将摸牌，给暗将不摸；暗将不能给明将**。
- **君主换牌**：`HegUtil.convertCards`（`util.lua:988-995`）把身份版名字映射为国战版
  （如 雌雄双股剑 → 飞龙夺凤），`build_draw_pile` 时把**被替换的原牌移出游戏**（`new_hegemony_mode.lua:540-558`）。

## 4. 势力可见性（bot 的核心议题）

**铁律：暗置武将的势力/技能/性别对他人不可见 ⇒ 势力推断必须「从可见事实推断」，绝不能读真值。**

### 4.1 ★ 两侧 bot 现状：**都在偷看**（已复核）

| | 老项目 | FreeKill |
|---|---|---|
| 敌友钩子 | `AI::GetRelationHegemony`（`src/server/ai.cpp:54-74`） | **`new_heg_mode:friend_enemy_judge`**（`new_hegemony_mode.lua:601-603`） |
| 偷看路径 | 未明置时读 `room->getTag(objectName).toStringList().first()` —— 该 tag 是**开局写入的真武将名**（`room.cpp:3758`） | `H.compareExpectedKingdomWith` 在 `from.kingdom=="unknown"` 时回退读 `from:getMark("__heg_kingdom")` —— 玩家**私下选的初始势力** |
| AI 调用链 | `isFriend()` | `SmartAI:isFriend`（`ltk/server/ai/smart_ai.lua:509`）→ `ServerPlayer:isFriend`（`serverplayer.lua:741`）→ `gameMode:friendEnemyJudge` |
| 推断层 | ✔ 有：`SmartAI:evaluateKingdom`（`smart-ai.lua:890-935`）+ `sgs.ai_loyalty` 概率表 | ❌ **无**（`evaluateKingdom` / `ai_loyalty` 全库 0 命中） |

⚠️ **不要以为 FreeKill 会落到身份局默认实现** —— `new_heg_mode` **有自己的** `friend_enemy_judge`；
落到身份局默认（读 `role`）的是 `freekill-core/standard/pkg/init.lua:221-228`。
**但「偷看」这个结论成立**，只是路径不同（`__heg_kingdom`）。

### 4.2 对参数标定的后果（**顺序硬约束**）

现在的 `isFriend` 都是「全知」的 ⇒ **在"全知假设"下标定出来的参数，一换成真实推断就全错**。
→ **势力推断（B3）必须早于参数标定（B8）**。

### 4.3 可见性数据侧的已知坑（A 线）

老录像的客户端快照**本身就泄漏真值**（`setActualGeneral1Name/2Name` 走 `doBroadcastNotify`、
`kingdom` 走 `broadcastProperty`）⇒ **"照录像重放即得正确可见性"只对卡牌成立，武将/势力必须显式掩码**
（已由 `mask_sensitive.py` + `record-dump.cpp:playerJson(p,selfId)` 两层防御）。
