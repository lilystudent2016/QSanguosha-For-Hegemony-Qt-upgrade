# 规则集基线（结算流程与时机的官方依据）

> **一句话定位**：规则集用来回答「**怎么结算、什么时机、按什么流程**」；
> 具体技能长什么样，**以目标项目的现役代码为准**（官方武将在持续调整，规则集非实时更新）。

技能三件套的中文口径以**目标项目**为准；**过程**（时机/流程/用语）以**规则集**校准。
规则集已本地化，不必联网。

## 一、知识库位置与两套来源

### 这个知识库**不负责**什么 —— 先看清楚

它**不是**"技能描述的标准答案库"。官方线上武将不断修改调整，规则集**不是实时更新的**，
里面的技能描述**可能已经老旧**。所以：

- ✅ 查：**结算流程、处理方式、时机、事件顺序、优先级、用语定义**
- ❌ 不查：某个技能**现在**应该写成什么文本 ← 这个**以目标项目现役代码为准**

## ★★ 分工总纲：规则集管「过程」，项目管「内容」

**先用这一节校准预期，再看后面所有内容。**

知识库的目的是**明确官方的结算流程与处理方式**，最终要落到代码里 ——
即「按目标项目代码的结算流程和时机触发方式去实现技能」。因此：

| 要确定的东西 | 谁说了算 | 规则集的角色 |
|---|---|---|
| **结算流程、处理方式、时机、事件顺序、优先级** | ★ **规则集** | **权威依据，照它写** |
| **用语定义**（`可`/`须`/`需`、`▶`、`并`、`依次`、术语表） | ★ **规则集** | 决定 `cost()`/`effect()` 切分与原子性 |
| **某个技能当前长什么样（描述内容）** | **目标项目现役代码** | 只作**对照参考**，**不照抄** |

### 为什么技能描述不能拿规则集当标准答案

**官方线上的武将在不断修改调整，而官方规则集不是实时更新的** ——
规则集里的技能描述**可能已经老旧**。

- ✅ 用规则集回答：「这个技能该**什么时机**触发」「结算时**先处理谁**」「这个操作是**同时**还是**依次**」
- ❌ 不要用规则集回答：「这个技能**现在**应该写成什么文本」

→ **具体技能描述以新的项目为准**；规则集用来校准**过程**。

### 遇到分歧怎么办（两种分歧要分开处理）

| 分歧类型 | 处理方式 |
|---|---|
| **规则集内部**（网页版 × 印刷本） | 按下方裁定 1：默认走网页版 |
| **规则集 × 目标项目** | **以项目为准写实现**，同时**列出差异让用户裁定** |

⚠️ 第二种分歧的两侧都可能是"错"的一方：
可能是**项目没跟上官方调整**，也可能是**规则集那版已过时**。**不要自行判定，问用户。**

## ★ 来源优先级（已定裁定 2026-09-17）—— 注意：只在**规则集内部**生效

| # | 裁定 | 对写代码的含义 |
|---|---|---|
| 1 | **描述冲突 → 默认走网页版**；印刷本只作**旁证** | 规则集**两源**不一致时照网页版；但**不适用于**「规则集 vs 项目」的分歧 |
| 2 | 印刷本独有技能 7 个（伪·鼓舌／决偃／存嗣／擎政／神驱／雪恨／骁战）**不补录** | 遇到这些技能名在网页版查不到，**属正常**，用 `--grep-print` 查印刷本即可 |
| 3 | 推论：**网页版未收录时，印刷本升为主依据**（唯一来源） | 仅适用于 38 张基础牌（基本牌 + 普通锦囊）+ 1 个武将（赵广&赵统）—— 这些没有别处可查 |

### 为什么印刷本只能当旁证（实测依据）

印刷本是 Acrobat OCR，**314 个技能页里只有 169 页（54%）文本可放心引用**：

| 等级 | 乱码率 | 占比 | 能不能引用 |
|---|---|---|---|
| 优 | < 0.18 | 12% | 可直接引用 |
| 良 | < 0.25 | 42% | 可直接引用 |
| 差 | < 0.35 | 37% | 可粗读，**逐字引用前核对原页** |
| 劣 | ≥ 0.35 | 9% | **只可出图人工核对** |

`--print` 会在页眉直接打出等级（如 `乱码率 0.29 等级「差」`）。
**等级「差」及以下不要直接抄进代码。**

### `--diff` 用的时候要守规矩

`--diff <技能名>` 会告诉你印刷本印证了网页版的第几版（多版本技能特别有用）。
但它**只能单向解读**：

- ✅ 「印刷本印证了第 2 版」→ 说明第 2 版在 2018-12 就存在，可信度提高。
- ❌ 「印刷本未印证第 3 版」→ **不能**推出网页版第 3 版有错 —— 同样可能是 OCR 弄坏了。
- 阈值由反向对照实测标定：错页覆盖度 0.06–0.33，本页 0.64–1.00，分界 0.50。

## 二、动手前必须做的几次查询

生成任何技能之前按顺序查一遍 —— 这比读参考文档更能防止选错基类。

**先明确去规则集查什么**：查的是**时机、流程、用语**（权威）；
技能描述本身只作**对照**（内容以项目为准）。

| # | 命令 | 拿到什么 | 属于 | 防止什么 |
|---|---|---|---|---|
| 1 | `--grep <时机关键词>` 或读 `data/时机表.md` | `❶❷❸` 对应的确切时机、该时机还能发动哪些技能 | ★ **过程** | 事件钩子挂错时机 |
| 2 | `--read 1917 1960` / `--toc` | 各类事件的结算流程原文 | ★ **过程** | 结算顺序/优先级写错 |
| 3 | `--general <武将> --mode <模式>` | 该模式下的版本与技能清单（**供比对**，非标准答案） | 内容·对照 | 抄错规则版本 |
| 4 | `--skill <技能名>` | 描述（**参考**）+ 官方原描述 + 出处 + ★印刷本页码与 OCR 等级 | 内容·对照 | 完全凭记忆写 |
| 5 | `--print <印刷本页码>` | 印刷本原页条文（旁证），页眉带 OCR 可读性等级 | 内容·旁证 | 单一来源的错误 |
| 6 | `--diff <技能名>` ⓘ | 规则集**内部**两源印证情况；未印证的不等于错 | 内容·自检 | 误把 OCR 失真当成规则冲突 |
| — | `--priority` | 复查来源优先级裁定全文 | — | 忘了裁定 |

**★ 技能描述以目标项目现役代码为准**（规则集非实时更新，可能老旧）——
上面 3/4/5/6 拿到的都是**对照material**，不是要照抄的标准答案。

ⓘ 多版本技能（`--skill` 返回 3 条以上描述）建议跑一次 `--diff`，能看出哪些版本是 2019 后新增的。

补充查法：

```bash
# —— 过程（权威）——
python tools/lookup_ruleset.py --grep 濒死 --limit 5 --context 2   # 用语定义、裁定案例
python tools/lookup_ruleset.py --toc && python tools/lookup_ruleset.py --read 1917 1960
# —— 内容（对照）——
python tools/lookup_ruleset.py --card 过河拆桥
python tools/lookup_ruleset.py --card 青釭剑        # 网页版有 → 同时给印刷本并列版本
python tools/lookup_ruleset.py --print 164
python tools/lookup_ruleset.py --grep-print 结算的方向
python tools/lookup_ruleset.py --toc-print
python tools/lookup_ruleset.py --legend
python tools/lookup_ruleset.py --deck 诸葛连弩
python tools/lookup_ruleset.py --coverage
python tools/lookup_ruleset.py --priority
python tools/lookup_ruleset.py --diff 咆哮
```

## 三、取哪一版描述

> ⚠️ 本节讲的是**规则集内部**怎么取版本。**最终实现以目标项目为准** ——
> 本节结果是"对照材料"，用来和项目比对、发现差异，不是"照抄标准答案"。

### 3.1 `官方原描述` vs `规则集规范描述`

源文档两种混排，`lookup_ruleset.py` 会标出：

- **〔官方原描述〕** = 官方牌面 / 线上原文 —— 用于对照玩家直觉。
- **〔规则集规范描述〕** = 规则集规范化改写，**补全了时机与操作语义**。
  → **用来提取"过程"（时机、消耗/效果切分、结算顺序）**；
  文本本身**不是**要照抄的最终文案 —— **技能描述以目标项目现役代码为准**。
  ⚠️ 规则集非实时更新，这一版**可能已老旧**。

`generals.json` 里每个武将按 `版本号`（⒈⒉⒊…）区分版本，`版本号 → 模式` 才决定技能属于哪个模式。
**做国战只取 `模式 == 国战`**。

### 3.2 印刷本的版本符号（网页版没有这张表）

印刷本给每张牌 / 每个武将条目标注了**产品线符号**，用来区分同名技能的不同版本。
**OCR 会把这些符号全部丢掉**，所以自动抽取的结果里没有版本信息 —— 需要判版本时要靠：

1. `--legend`（= 印刷本 p9 的 29 个符号），与国战直接相关的 5 个：
   **国战模式·标准版 / 国战SP / 君临天下·势备篇 / 势 / 阵 / 变**；
2. 文本特征反推：出现「势力」「对手」「队友」「明置」「暗置」「主将」「副将」「大势力」
   → 高度可能是国战版（`2019ocr_cards_verified.json` 里已标 `推断版本` 字段）。

## 四、拆句依据：记号与关键词（都在规则集里有定义）

**这一节是"过程"范围 —— 规则集说了算。** 但注意：
规则集给出的是**语义**（消耗、同时、依次、可选…），**不是项目里的字段名**，
见 §10「术语翻译表」。

| 记号／关键词 | 行（主规则集.md） | 含义 | 落到代码 |
|---|---|---|---|
| `▶` | 825 | 左 = **消耗**，右 = **效果** | 消耗 → `cost()` ／ 效果 → `effect()` |
| `▷` | 829 | **条件效果链**：执行了左效果才执行右效果 | 顺序 if，语义上不可并行 |
| `→` | 833 | 右侧是**延时类效果**（有独立执行时机） | 单独触发技 / 延时标记 |
| `并` | 889 | 两操作**同时执行**；一个不能执行则都不可执行 | 原子化，不能拆两步 |
| `依次` | 855 | 操作一张后重复 X−1 次 → **逐个结算** | 循环 + 每步重查 |
| 无「依次」的 X 张牌操作 | 867 | **一次性同时操作** | 不要循环 |
| `可` | 787 | 主语有权选择是否发动／执行 | `triggerable()` 返回可选 / `askForSkillInvoke` |
| `须` | 885 | **强制**执行 | `frequency = Compulsory` |
| `需` | 881 | 主语有权选择**如何响应** | `askForChoice` / `askForCard` |
| `/` | 819 | 该技能是两个结构相同的技能合并写法 | 拆成两个技能 |

`可` 在**消耗前**和**效果前**含义不同（规则集 787 条有分述），这决定 `cost()` 里要不要
`askForSkillInvoke`、`effect()` 里还能不能中途放弃 —— 是最常被写错的一处。

`〖〗` 标技能名、`【】` 标牌名、`" "` 标标记（如“田”“幻”）、`{ }` 表示句内逻辑层次。

## 五、时机（`❶❷❸`）

描述里的 `❶❷❸` 是**时机序号**，不是装饰。查 `data/时机表.md`：

- 该表按事件类型（技能使用 / 需要使用牌 / 预使用 / 使用 / 需要打出 / 预打出 / 打出 / 拼点 /
  移动 / 牌状态改变 / 判定 / 伤害 / 失去体力 / 扣减体力 / 回复体力 / 减体力上限 /
  加体力上限 / 濒死 / 死亡）逐个列出**由先到后**的全部时机；
- 每个时机还标出了**当场能发动的武将技能与装备技能** —— 这是校验时机切分对不对的现成样本；
- 例：`其需要使用此牌时❶能发动的装备技能：〖八卦阵〗` → 该时机对应“需要使用【闪】时”的钩子。

同一时机多技能并发时，按主规则集第一章「优先级确定原则」裁定。

## 七、规则版本警告（必须让用户裁定）

有四层版本，**任意两层不一致都可能是问题**：

| 层 | 版本状态 |
|---|---|
| 老项目 `QSanguosha-For-Hegemony-xxyheaven` | 依据 **2014 规则书** |
| 规则集 网页版 | 含 **新国战标准版2019**、**君临天下**（权/变/阵/势）；2019 后停更 |
| 规则集 印刷本 | 定格在 **2018-12** |
| **目标项目（最终落点）** | **现役，持续更新** ← **技能描述以此为准** |

**官方线上的武将在不断修改调整，规则集不是实时更新的** →
老项目的 2014 直觉、规则集的 2019 文本，**都可能与项目现役实现不一致**。

处理原则：

- **技能描述（内容）** → 以**目标项目**为准。
- **结算流程/时机（过程）** → 以**规则集**为准（这是它唯一权威的地方）。
- **两者冲突** → 以项目写实现，**列出差异让用户裁定**，不要自行判定谁对。
  ⚠️ 两侧都可能是"错"的一方：可能项目没跟上官方调整，也可能规则集那版已过时。

## 八、印刷本 OCR 的可靠性（引用前必看）

印刷本 OCR 有稳定的错字类型：「弃置」→「弃笃/弃宣/弃笸」、「距离」→「跑离」、
「造成」→「遣咸」、「目标对应」→「旬叙寸应」、「重置」→「正监」、`►` → `·`。

`data/2019ocr_cards_detail.json` 每条带 `乱码率` 与 `OCR可疑` 字段：

| `OCR可疑` | 引用方式 |
|---|---|
| `false` | 可直接引用，但明显错字要按上表还原 |
| `true` | **必须回原页核对**：`--print <页码>`，或用 `tools/render_pages.py <页码>` 出 PNG 用多模读图 |

`data/2019ocr_cards_verified.json`（22 张）是**逐页打开原图读取**的结果，可直接当规范文本。

### 8.1 卡牌级：`OCR可疑` 标记

上表已列出引用方式。**`OCR可疑=true` 必须回原页核对。**

### 8.2 页面级：乱码率分级（比卡牌级更粗的门槛）

| 等级 | 乱码率 | 能不能引用 |
|---|---|---|
| 优 | < 0.18 | 可直接引用 |
| 良 | < 0.25 | 可直接引用 |
| 差 | < 0.35 | 可粗读，**逐字引用前核对原页** |
| 劣 | ≥ 0.35 | **只可出图人工核对** |

`--print` 页眉会直接打出等级。**314 个技能页里只有 169 页（54%）属于优/良。**

### 8.3 ⚠️ 技能名在 OCR 里基本丢了

印刷本的**技能名是图形化标题**，OCR 通常整块丢失 —— 例：p566 是【联翩】的条文页，
但整页**搜不到「联翩」二字**。

→ 想在印刷本里定位某个技能，**不要搜技能名**：

- 用 `--grep-print <条文关键词>` 搜正文；
- 用 `--skill <技能名>` 拿页码（索引是完整的，638 条）；
- 用 `--diff <技能名>`（内部按整页滑窗对齐，不依赖技能名出现）。

若要新增核对条目：先 `render_pages.py` 出图 → 读图 → 把结果写进
`tools/curate_2019ocr.py` 的 `V` 列表 → 重跑该脚本（数据即文档，别手改产物文件）。

## 九、已知缺口

1. 网页版备份里 `游戏牌/锦囊牌/普通/` 为**空目录**、无 `基本牌/` →
   【杀】【闪】【桃】【酒】与普通锦囊没有单卡文件。**该缺口已由印刷本补上**
   （`md/2019OCR/精选/人工核对-基本牌与普通锦囊.md` + `data/2019ocr_cards_verified.json`）。
   → 此处**印刷本是唯一来源**，按 ★ 节裁定 3 **升为主依据**，照印刷本写。
2. **7 个印刷本独有技能不补录**（伪·鼓舌／决偃／存嗣／擎政／神驱／雪恨／骁战）——
   按 ★ 节裁定 2，这不是缺口、不是待办。在网页版查不到它们是正常的，
   需要时用 `--grep-print` 查印刷本条文。
3. 印刷本**没有国战牌堆统计**（第一章「游戏牌统计」只针对身份模式）→
   国战的牌堆构成仍需另找来源或由用户裁定。
4. 网页版规则集脚注（`[1]` `[2]` 如“三原色注”“会智迟的沮授注”）正文散落在各文档末尾，
   转换时未与正文合并，需要时自行在源文件里查。
5. `md/主规则集.md` 里形如 `#身份牌` 的行是原文以 `#` 开头的标签段落，被 Markdown
   误判为标题，**不代表真实层级**。
6. 印刷本**没有独立的基本牌/普通锦囊 `.md` 单文件**——是集中在
   `md/2019OCR/精选/人工核对-基本牌与普通锦囊.md` 一篇里，按 `--card` 查更省事。
7. 印刷本技能名在 OCR 里丢失（见 §8.3），**不能用搜技能名的方式定位条文**。

## 十、术语翻译表：规则集用词 → 项目字段

**规则集的"过程模型"是权威的，但"用词"不是。**
不要照搬规则集的名词当代码标识符 —— 先查目标项目里对应的字段/概念再落笔。

| 规则集用词 | 语义 | 落地时怎么找项目里的对应物 |
|---|---|---|
| 使用者 | 发动牌/技能的角色 | 项目里通常是 `from` / `who` / 技能所有者 |
| 目标 / 目标对应的角色 | 被指向的角色 | `to` / `target` / `targets` |
| 最终目标列表 | 结算完毕后的目标集合 | 项目里可能是 `to` 快照 / targets 列表 —— **名字与结构都不一样** |
| 区域 | 手牌区/装备区/判定区 | `place` / `PZ` / `card->getArea()` 类字段 |
| 消耗 `▶` 左 | 发动前要付的东西 | 对应项目里的 cost 回调（`cost()` / `onCost` / `feasible`） |
| 效果 `▶` 右 | 发动后的结果 | 对应 effect 回调（`effect()` / `onEffect`） |
| 时机序号 `❶❷❸` | 同事件内的先后位次 | 项目的事件枚举名 —— 用 `data/时机表.md` 定位后再查项目事件表 |
| 明置 / 暗置 | 武将牌是否可见 | 国战里 `__heg_*` 标记类字段 |

**做法**：先在规则集里把过程读清楚（这句是消耗还是效果？是同时还是依次？什么时机？），
**再**去目标项目里找对应的机制和字段名，用**项目的词汇**写代码。
