## 咨询：老项目（Qt 5.14）升级新版 Qt 的必要性与工作量评估

给用户的分析结论（基于实际读工程得出）：
- 工程为 qmake `.pro`；UI 层全部基于 QGraphicsView（roomscene/carditem/dashboard 等）；
  音频用 FMOD（fmodex 老 DLL）；FreeType；Breakpad 崩溃收集；内嵌 Lua + SWIG 包装；QtQuick 仅 `ui-script/animation.qml` 一处。
- **Win11 兼容性本身不是问题**（Qt 5.14 程序在 Win11 正常），真正的痛点是高 DPI 缩放。
  仅需在 main.cpp 加 `AA_EnableHighDpiScaling` / `AA_UseHighDpiPixmaps` 或环境变量 `QT_ENABLE_HIGHDPI_SCALING=1` 即可缓解。
- 升 Qt6 的机械改动点：QRegExp → QRegularExpression（20+ 文件在用）、qrand/endl/QDesktopWidget 等废弃 API、
  FMOD 建议换新版、Breakpad 建议换 Crashpad、SWIG 重新生成、qmake → CMake（可选）。
- 工作量估计：熟悉项目的开发者 1~3 周；大头不是 API 改名，而是高 DPI 下 QGraphicsView 场景的视觉调试。
- 建议：短期维持 5.14 + 高 DPI 补丁（半天~一天）；中期若持续维护则升 Qt 6.8 LTS；不建议重写 UI。

- 用户背景：C/C++/TS/Lua 基础语法 OK，能读懂武将技能实现；Qt GUI（动画、信号槽）、网络、音频零经验。
- 给出「四色分区」建议：绿灯= Lua 扩展/文案/AI/数值；黄灯= C++ 技能（有 qsgs-skill-generator 三件套生成器）；
  橙灯= Qt 界面与动画（主观标准，只能截图迭代）；红灯= 网络协议/房间流程/音频引擎（无回归测试兜底，建议避开）。

## 调研：跨项目移植路线（resgs / FreeKill）与许可约束

用户诉求：把网页版三国杀（resgs）界面移植进老 Qt 项目，或反过来把老项目人机逻辑移植进 resgs；
并问能否打包成桌面/手机、新老项目哪个更好维护。

### resgs（github.com/guiling0/resgs）事实
- TS 全栈：`shared/`（纯 TS 事件驱动引擎，服务端/客户端共用）、`server/`（Node + Colyseus 0.17 + MongoDB）、
  `client/`（**LayaAir 3.4** H5 游戏引擎，非 React/Vue）、`wiki/`、`knowledge/`（@rules 知识库）、`extension/`（SkillBuilder 扩展体系）。
- 仓库 2026-07-15 创建、最后 push 2026-08-08；0 star / 0 fork；size 128MB。
- **无 LICENSE 文件（GitHub API license = null）→ 默认保留所有权利，复制其代码无授权**。
- `shared/core/` 只有 builder/entity/logic/state/transport/types/utils + sgs.ts/ILogger.ts/ConsoleLogger.ts
  —— **没有任何 ai/bot 模块**，只有「AI 设计文档」，即 AI 尚未实现。
- README 提到 `old/ 旧项目（移植参照）`，即作者自己也在做老项目移植；有 R0-R10 移植路线图。

### FreeKill（github.com/Qsgs-Fans/FreeKill）事实（更强的宿主候选）
- 「An open source board game engine, written in Qt and Lua」，topics: card-game/lua/qml/qtquick；
  Qt6 + QML 前端 + Lua 技能逻辑；982 star / 108 fork；2022-02 创建，2026-09-08 仍在提交；**GPL-3.0**。
- 文档：fkbook-all-in-one.readthedocs.io。与老项目同为 GPLv3 → **法律上可互通移植**（Lua→Lua，成本远低于 Lua→TS）。

### 老项目许可
- 代码：GPLv3（Copyright 2015-2016 Mogara，见 `LICENSE`）。
- 素材：`CC BY-NC-ND 4.0`（非商业 + **禁止演绎**；可原样非商业分享，不可分享改编后的素材）。

### 结论要点
- 「把 resgs 的 LayaAir 界面搬进 Qt 项目」无代码可搬，等于重写 UI（不推荐）。
- 「老项目 Lua AI（497 技能、108 hook 已补齐）→ TS」可行但是「从零建 AI runtime + 逐技能翻译 + 等价性回归」。
- 打包：LayaAir 客户端可 Tauri/Electron 包 Windows、LayaNative/Capacitor 出移动端；单机人机无需服务器，联机才需要。
- 维护成本：新 TS 项目远低（npm/typecheck/测试框架 vs Qt5.14+MSVC+qmake+FMOD+SWIG），但老项目才有完整可玩资产。

### 核心结论
**要移植的不是"人机对战逻辑"，而是"技能集 + AI 策略知识"**，且 FreeKill 已预留兼容层。

### 实测关键事实（重要，后续复用）
- FreeKill 技能是**单文件收敛**：`packages/<pkg>/pkg/skills/<skill>.lua` 内含
  `addEffect`（逻辑）+ `addAI`（AI）+ `addTest`（测试）；中文在 `packages/<pkg>/i18n/zh_CN.lua`。
  老项目则是三处分散（src/package/*.cpp + lang/zh_CN/Package/*.lua + lua/ai/*-ai.lua）。
- **FreeKill 内置"神杀智慧"兼容层**：`lua/server/ai/smart_ai.lua:68-121` 的 `qsgs_wisdom_map`，
  注释原文「神杀智慧之 sgs_ex.lua: 致敬传奇靠造表创建对象写法」。映射关系：
  `ai_skill_invoke→think_skill_invoke`、`ai_skill_choice→think_choice`、
  `ai_skill_playerchosen→choose_targets`、`ai_skill_cardchosen→think_card_chosen`、
  `ai_skill_discard→choose_cards`、`ai_skill_use_func→think`。
- FreeKill AI 是**收益论驱动**：`SmartAI:getBenefitOfEvents(fn)`（smart_ai.lua:474），
  传一段模拟操作即得收益值 → 老项目大量"if 血少 then 发动"的手写启发式在 FreeKill 里
  **不必逐字翻译，用收益计算重写更短更强**。这是移植的最大杠杆点。
- **不要移植 `lua/ai/smart-ai.lua`（7096 行）的通用启发式**，FreeKill 有自己的通用 AI。
- 规模：老项目 AI 约 37,746 行 Lua / FreeKill 引擎侧 AI 仅约 1,916 行。
- FreeKill 有测试体系（`addTest` + FkTest），标准包 18 个技能带测试 → **测试就是移植的验收标准**。

### 环境经验（复用）
- Windows Git Bash 里 PATH 缺 `/usr/bin`，需 `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Windows:$PATH"`。
- PowerShell 工具在本会话返回空输出，用 Bash + export PATH 更可靠。
- 本项目 .pro/.cpp 里 C++ 技能名要靠**基类构造的第一个字符串字面量**提取
  （`Jianxiong() : MasochismSkill("jianxiong")`），不能靠 CamelCase 类名反查拼音。
