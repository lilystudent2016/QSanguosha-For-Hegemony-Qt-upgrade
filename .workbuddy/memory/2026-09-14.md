## 创建 Skill：qsgs-skill-generator（三国杀技能三件套生成器）

用户诉求：从 package 里的中文技能说明，生成对应的 C++ 技能代码 + Lua 格式的技能 AI。

### 交付物
用户级技能 `~/.workbuddy/skills/qsgs-skill-generator/`：

- `references/cn-to-cpp.md` —— 中文措辞 → TriggerEvent / 可选性 / 频率 的映射表

- `references/examples.md` —— 奸雄 / 裸衣 / 倾国 / 驱虎 四个端到端实例

### 本项目关键事实（后续复用）
- 技能三件套落点：`lang/zh_CN/Package/*.lua`（中文名 `["x"]` + 描述 `[":x"]`）、`src/package/*.cpp/.h`（C++ 类 + `addSkill`）、`lua/ai/*-ai.lua`（AI）
- lang 文件名与 package 名**不总一致**：`newsgs.cpp`/`mol.cpp` 的中文在 `LordEXPackage.lua`；装备/牌类技在 `StandardPackage.lua`。必须 grep 实测，不要凭名字猜。
- `SkillCard` 子类必须声明在 `.h`（`Q_OBJECT` + `Q_INVOKABLE`），否则 moc 不生成元对象，运行期静默失效。
- 无需 `Q_OBJECT` 的技能类直接写在 `.cpp`；跨 package 复用才提到 `.h` 并用 `explicit Xxx(const QString &owner)`
- 共享技能用 owner 后缀命名：`DistanceSkill("mashu_" + owner)`，lang 里为每个实例单独起条目（`mashu_machao`）
- AI hook 键名归一化：`askForSkillInvoke` / `askForCardChosen` / `askForAG` / `askForPlayersChosen` 会把技能名里的 `-` 换成 `_` 再查表
- `sgs.ai_skill_use_func` 的键是 **SkillCard 类名**（`QuhuCard`），不是技能名
- `extension-doc/12-SmartAI.lua` 已滞后：其中提到的 `sgs.ai_chaofeng` 在当前代码中不存在，以代码为准
- 视为技不写 `sgs.ai_view_as` → AI 永不使用该技能（最常见的"AI 不会用"根因）

### 环境注意
- Git Bash 里 `PATH` 缺 `/usr/bin`，需先 `export PATH="/usr/bin:/bin:/c/Windows/System32:$PATH"` 才能用 ls/grep/sed 等
- 向 Windows python 传脚本路径必须用 `C:/...` 形式，`/c/...` 会被解析成 `C:\c\...`

### 本轮修掉的 bug（都经真实数据回归）
1. `inspect_skill.py` 把**注释**当真实代码：模板里 `// addSkill(new Xxx);` 会让未注册的技能报"已注册"。
   修法：扫描前按等长空格屏蔽 C++/Lua 注释（行号不变 + 长度校验防误吞）。
2. `inspect_skill.py` 传 `/c/...` 路径不报错，只把三处全报"缺失"。修法：加根目录合法性校验。
3. `inspect_skill.py` 新增技能卡 `addMetaObject<XxxCard>()` 检查（本轮当场抓到演示代码的问题）。
4. `parse_lang.py` 把「出牌阶段」误判为触发时机 → 形态判成 TriggerSkill。修法：区分 trigger / active。
5. `parse_lang.py` 把 `quhu` 描述里"其对其攻击范围内"误判成 `AttackRangeSkill`。修法：规则修正型措辞收紧为指向自身属性（"你的攻击范围±N"）。
6. `parse_lang.py` 取错主时机（`luoyi` 取到"造成伤害时"）。修法：主时机取描述中位置最靠前者，其余列为"次要时机"并提示拆内部技。

### 新掌握的项目事实
- lang 键位：`["武将名"]` = 武将名、`["#武将名"]` = 武将称号（如 `["#caocao"] = "魏武帝"`）、
  `["illustrator:武将名"]` = 画师、`["技能名"]` = 技能名、`[":技能名"]` = 描述、
  `["@技能名"]`/`["@技能名-后缀"]` = 询问提示、`["~技能名"]` = 操作指引、
  `["技能名:choice"]` = askForChoice 选项标签、`["#XxxBuff"]` = 日志文案、`["$技能名N"]` = 语音（在 Audio/*Lines.lua）
- 技能判定规则：同时存在 `["K"]` 与 `[":K"]`（或 `["@K"]`/`["~K"]`）才算技能
- `Player::Phase` 枚举：RoundStart, Start, Judge, Draw, Play, Discard, Finish, NotActive, PhaseNone
  （准备阶段 = `Player::Start`，结束阶段 = `Player::Finish`）
- 引擎签名：
  `bool askForDiscard(ServerPlayer *target, const QString &reason, int discard_num, int min_num, bool optional = false, bool include_equip = false, const QString &prompt = QString(), bool notify_skill = false)`
  `QString askForChoice(ServerPlayer *player, const QString &skill_name, const QString &choices, const QVariant &data = QVariant(), const QString &prompt = QString(), const QString &all_choices = QString())`
- `SkillCard::extraCost` 默认实现 = 把 subcard 移入弃牌堆，所以"弃置一张牌"的消耗只需 `SkillCard::extraCost(room, card_use)`
- 视为技 / 技能卡形态**不经过** `askForSkillInvoke`，配 `ai_skill_invoke` 无用，要配 `ai_skills` + `getTurnUseCard`
- 演示沙箱（可复用的回归夹具）：`.workbuddy/skill-demo/sandbox/`（最小 QSanguosha.pro + 三件套落位），
  用 `inspect_skill.py <skill> --root <沙箱路径>` 即可验证生成物而不动真实源码

### 审计工具

### 关键经验（易踩坑）
1. **同一个 .cpp 里的技能可能分属不同 package**，AI 必须写进各自 package 的 `-ai.lua`：`newsgs.cpp` 里 `ManoeuvrePackage`(wanggui…xunchen) 的 AI 在 `manoeuvre-ai.lua`，`NewSGSPackage`(jianggan/yangwan/…) 的在 `newsgs-ai.lua`。
2. **排序语义**（`lua/ai/smart-ai.lua`）：`sortByUseValue(cards)` 默认**降序**（+true 升序）；`sortByKeepValue(cards)` 默认**升序**（+true 降序）；`sort(players,"hp")` 默认升序。→ 拆/偷敌方用 useValue 默认；拆/弃友方用 keepValue 默认。
3. **`askForCardChosen` 实际会先走 `ai_skill_cardschosen`**（`Room::askForCardChosen` 内部调 `askForCardsChosen(min=max=1)` → `SmartAI:askForCardsChosen` 先查 `ai_skill_cardschosen[reason]`，未命中才落到 `ai_skill_cardchosen`）。所以同名技能（如 fenglve/weimeng）的两个 key 要都定义、且逻辑一致。
4. 回调签名：`ai_skill_discard(self,discard_num,min_num,optional,include_equip)`；`ai_skill_cardschosen(self,who,flags,min_num,max_num,method)`；`ai_skill_cardchosen(self,who,flags,method,disable_list)`→id/-1；`ai_skill_playerchosen(self,targets,max_num,min_num)`→玩家或表。
5. `askForPlayerChosen` 也是走 `ai->askForPlayersChosen(targets, reason, 1, 0/1)` → 归到 `ai_skill_playerchosen`（单个返回 ServerPlayer 会被自动包成表取 first）。
6. 追加补丁用 `.workbuddy/skill-demo/append_patch.py`（归一化 LF→CRLF + 首行注释做幂等指纹）；语法校验用 `.workbuddy/skill-demo/check_lua.py`（lupa，无独立 lua 二进制）。
7. `mol.cpp` 的 `kenshang`/`#kenshang-effect` 是**未接线代码**（无 addSkill、无 lang 条目），已按其设计意图补 AI 并在 mol-ai.lua 内注明。
